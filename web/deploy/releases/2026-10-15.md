## Compatibility

The hosted catalog has 18 games. Red, Blue, Yellow, Gold, Silver, Crystal,
FireRed, and LeafGreen retain the existing Gen1Recomp/LÖVE engine. Existing
Emerald `.pws` saves also keep that engine; new native Emerald slots use 128 KiB
raw `.sav` files. All seven native DS games use 512 KiB raw saves. One optional
Neon cloud save per account is preserved, with no new paid cloud resource.

The native runtime supports reset/reset_carry and single-screen guests. Large
cartridges use IndexedDB Blobs; older ArrayBuffer records remain readable.
No cryptography or network persistence was added to the frame loop. Native
games require no WebGL; the existing LÖVE engine still requires WebGL. Its
experimental Canvas renderer is not part of this release.

## Deployment

Live revision: `nativeplat-00011-tss`, serving 100% of traffic at
https://pokeweb.morisoba.moe/ and the existing Google service URLs.
Image tag: `20261015-native-wasm-memory`; resolved platform image:
`us-east1-docker.pkg.dev/nativeplat-20261004/nativeplat/web@sha256:4e58b4b04d08b6bbdf6fe8bfc191cd83df0f4e364a941e92137a8ac9e94637fb`.

Both custom-domain and Google-host sweeps passed all 18 encrypted cartridge
fingerprints, all engine/source/license digests, all ten native WASM digests,
600 runtime frames per native core, security/cache headers, and raw-cartridge
URL rejection. Fresh hosted browser sessions passed for Ruby, White, and
Platinum, including field saves and exactly one package request across first
play and cached reload. White's browser check was repeated on the final revision.

The live API passed secure sessions, login/logout, account isolation, invalid
upload rejection, stale-write protection, one-save replacement, and exact Neon
byte readback for all 18 games and both Emerald save formats. Verification used
generated fixtures and removed its temporary accounts; real game-save behavior
was checked separately with the read-only browser fixtures above.

Concurrent catalog downloads and API checks exceeded the former 512 MiB limit.
The container now pins nginx to one worker and bounds Node's old-space heap to
128 MiB. Those limits alone were insufficient at 512 MiB, so the service uses
1 GiB, one CPU, zero minimum instances, and a service-level maximum of three.
Both full catalog sweeps, the API checks, and a fresh White browser session then
passed concurrently, with no ERROR/OOM logs recorded for the final revision.
Future deploys default to 1 GiB; `NP_GCP_MEMORY` can override that setting.

Local Docker validation temporarily exhausted disk space. Only this release's
two disposable source snapshots were removed after build completion; their
provenance and build logs were retained under `build/release-evidence/2026-10-15`.
Final WASM, cartridge packages, browser reports, and original checkouts remain.
